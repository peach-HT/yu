# 工程问题与解决过程

本页将真实使用中的问题连接到实现和回归检查。本人提供失败场景、预期行为并参与验收；代码与自动检查由AI协作完成。

## 多个数字不等于多笔消费

**触发案例**：“吃饭花了20，饮料4”以及“消费35.5，其中吃饭30，饮料5.5”在实际语音输入中未得到正确处理。

简单提取所有数字再求和，无法区分总额、明细、日期、数量或余额。“35.5 + 30 + 5.5”会把同一消费计算两遍。

[voice.mjs](../dist/voice.mjs)先归一化文本、判断消费或校正意图，再基于金额单位、消费动词和项目词提取金额。提取时保留文本位置，避免重复计入同一区间；遇到“其中”等表达时识别总额与明细关系。

| 表达 | 当前规则 |
| --- | --- |
| 吃饭花了20，饮料4 | 合计2400分 |
| 消费35.5，其中吃饭30，饮料5.5 | 明细与总额一致，只生成3550分消费 |
| 总额包含未细分部分 | 保留总额并显示未细分金额，不强迫明细完整 |
| 明细超过总额或显式合计不一致 | 要求核对，不自动回填可提交的消费 |
| 同句同时说消费和余额 | 拒绝混合操作，提示分开记录 |
| 涉及优惠、实付等多个金额 | 不猜测金额关系，要求说明最终实际金额 |

这是面向特定场景的确定性解析，不是通用自然语言理解。项目词、句式与日期范围均有限；超出范围可以手动输入。

检查依据：[voice.test.mjs](../tests/voice.test.mjs)，其中包含上述真实失败原话，以及数量、时间和其他数字不能误当金额等场景。

## 累计事件和跨会话补充需要不同处理

浏览器识别事件中的results可能重复包含本会话之前的文本。如果每次收到事件都追加，前文会重复，金额也可能随之重复。

[speech-session.mjs](../dist/speech-session.mjs)每次重建当前会话的最终文本和临时文本；[voice-ui.mjs](../dist/voice-ui.mjs)仅将已确认的当前会话内容与之前草稿拼接。未完成的尾句不会静默回填。

继续补充与重新说分开处理：前者保留前文，后者替换旧草稿。不能按文本相同直接去重，因为“消费20元，又消费20元”可能确实是两笔消费。

检查依据：[speech-session.test.mjs](../tests/speech-session.test.mjs)检查累计结果重建和拼接；[voice-ui.test.mjs](../tests/voice-ui.test.mjs)模拟多段回调、跨会话补充，以及总额之后继续补充明细。

## 异步语音不能覆盖新的手动输入

用户可能在识别结束前关闭面板或开始手动修改。仅隐藏按钮不会阻止旧回调继续执行。

语音控制器使用递增token标识会话；关闭、取消、重新开始或手动编辑时作废旧token，回调先核对token再修改界面。最终文本经过规则校验后回填，保存仍需用户确认。

检查依据：[voice-ui.test.mjs](../tests/voice-ui.test.mjs)中的“手动编辑或关闭后迟到识别不覆盖字段，重新说替换旧草稿”。这些是模拟浏览器事件检查，不代表所有设备上的实际识别效果。

## 轻量本地工具也需要保护记录

储值消费需要避免浮点误差与超额扣减。领域规则以整数分计算，生成权益新状态和对应事件；事件记录前后余量以及版本，只有版本匹配时才能直接撤销。

面板提交前还会比较打开时的localStorage快照，发现状态变化则拒绝覆盖。这可以发现部分旧表单覆盖，但检查与写入不是原子操作，尚未解决真正的并发写入。

检查依据：[domain.test.mjs](../tests/domain.test.mjs)覆盖金额、有效期、超额和撤销规则；快照检查位于[app.js](../dist/app.js)，目前没有对应的跨标签页并发自动检查。
