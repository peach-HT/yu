# 工程迭代与测试依据

v13聚焦期限与使用足迹。本人提供真实失败场景、预期行为并参与验收，AI协助具体实现与自动检查。

## 当前：累计语音与迟到回调

浏览器可能重复返回包含前文的累计结果，直接追加会造成重复文本。speech-session.mjs每次重建当前会话文本，分开最终结果和临时结果；voice-ui.mjs将已确认结果与之前草稿拼接，支持“继续补充”和“重新说”。

手动编辑、关闭或重新开始时递增会话token，旧回调检查token后才能回填。未完成尾句不会静默回填。语音只回填日期与描述，用户确认后才保存。

依据：[会话文本检查](../tests/speech-session.test.mjs)、[模拟语音交互检查](../tests/voice-ui.test.mjs)。

## 当前：无金额语义与日期回填

“昨天健身”回填昨天；明确日期和全角数字日期也可解析。多个日期、未来或无效日期要求核对。金额描述按原话保留，明确余量校正请求提示当前版本不支持，避免用户误以为余额已更新。

依据：[语音规则检查](../tests/voice.test.mjs)。

## 当前：兼容升级与记录保护

直接移除旧字段的校验支持会让已有用户无法加载；直接清空它们则损失历史信息。v13选择保留旧数据、移除写入入口：新权益和事件不产生余量字段，旧消费及校正只读展示，不允许通过撤销改变旧余额。

新增模拟DOM流程检查，实际导入app.js执行录入、编辑、打卡、撤销、日历与存储逻辑，验证旧余额不变、历史事件保留，以及陈旧表单和损坏数据不被覆盖。

依据：[领域检查](../tests/domain.test.mjs)、[模拟界面流程检查](../tests/app.test.mjs)。模拟DOM不是完整真实浏览器验收。

## 当前：期限规则与信息状态

截止日期、日差、状态分层、排序和概览集中在expiry.mjs。今天、3天内、4—7天、已过期、未知日期与长期有效分别表达，颜色之外保留文字。

依据：[日期状态检查](../tests/expiry.test.mjs)。

## 历史探索：多金额解析，已退出当前版本

v12曾针对实际失败原话“吃饭花了20，饮料4”与“消费35.5，其中吃饭30，饮料5.5”，探索基于消费语境的金额提取、总额与明细校验、整数分计算，并加入回归检查。

此后判断：金额和次数一样都需要持续手动维护，违背轻量到期清单的范围。v13移除当前金额解析、汇总、扣减、余额校正和相关测试，保留这段经历说明技术探索如何服从产品取舍。

[查看v12代码](https://github.com/peach-HT/yu/tree/4aef74a7dba2217dad6615b7dae3abb17f184061)，[v12状态截图](images/expiry-states.png)包含历史金额，不代表当前UI。
