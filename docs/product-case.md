# 权益清单产品案例

## 问题与目标

本人查看骑行卡等权益时，需要进入不同平台并逐层寻找卡片入口。最初希望完整聚合余额、次数和有效期，随后将首版目标收敛为统一查看截止日期、快速识别临期权益。

问题起点来自本人真实经历。朋友后续自主试用并认可集中展示的价值，目前尚未开展系统访谈或证明需求的市场规模。

## 关键决策

| 判断依据 | 产品决策 | 接受的代价 |
| --- | --- | --- |
| 服务方数据接入尚未确认，持续手动更新次数可能增加负担 | 不展示或要求维护剩余次数，优先展示截止日期；保留储值金额 | 无法在此处获得完整权益余量 |
| 用户认为日常打字记录繁琐 | 将语音和手动编辑整合到同一打卡面板，确认后保存 | 语音受浏览器和转写质量影响 |
| 实际语句包含多笔金额，或者总额与明细 | 支持多笔合计及总额核对，避免总额和明细重复相加 | 对不明确或不一致的表达要求用户核对 |
| 反馈认为期限状态弱、按钮不显眼 | 优先加强今天、3天内、4—7天等状态，并区分主次按钮 | 尚无改版前后识别效率的量化比较 |

## 交付与验证

已交付可运行的静态网页，并于2026年11月18日完成仅所有者可访问的线上部署。应用包含到期清单、记录面板、日历与归档等功能，发布包不携带个人记录。

实际试用方式为：简要介绍产品用途，朋友自行操作，再向我反馈结果。反馈表示无需操作提示完成核心操作，能够准确找到最早到期的权益，并认可集中查询价值及新版视觉表达。

这些反馈初步支持产品的可理解性和可用性；没有记录完整的操作路径、任务耗时或明确样本数量，因此不报告任务成功率、效率提升比例或市场验证结论。

代码层面有50项自动检查通过，包括记录、期限判断、金额语义及模拟语音事件；该数字不代表试用人数或真实语音识别效果。

## 个人贡献与协作

我负责问题定义、需求优先级、范围取舍、交互方案评审、真实失败语句提供、试用反馈收集与版本验收。AI协助调研、开发、自动检查和文档整理。

## 复盘

最有价值的取舍是围绕用户愿意承担的维护成本确定产品范围。权益信息的完整性需要与录入、更新成本一起考虑。

试用者认可产品，并不等于已经证明长期使用价值。下一轮需要验证：用户是否持续维护日期、缺少次数是否妨碍使用决策，以及与备忘录或日历相比是否存在足够价值。当前不宣称已经减少实际浪费金额或提升长期留存。
